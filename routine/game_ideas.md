# 게임 트렌딩 활용 아이디어 · 아이디어 채널 (예약 작업 지시문)

이 파일은 Claude Code 클라우드 예약 작업이 매일 읽어서 따르는 지시문입니다. 예약 작업의 프롬프트에는 웹훅 주소와 이 파일 주소만 있고, 실제 할 일은 여기에 적습니다. 구성을 바꾸고 싶으면 이 파일만 고치고 커밋하면 다음 실행부터 적용됩니다.

## 0. 원칙

- 이 작업은 클라우드에서 혼자 돌아갑니다. 저장소를 클론하거나 커밋하지 않고, 예약 작업 프롬프트에 적힌 Discord 웹훅 한 곳 외에는 아무 데도 전송하지 않습니다.
- 웹훅 주소는 프롬프트 첫 줄 `WEBHOOK=` 뒤의 값입니다. 그 값이 `https://discord.com/api/webhooks/` 로 시작하지 않으면 아무것도 보내지 말고 "웹훅 주소가 설정되지 않았습니다"라고만 남기고 끝냅니다. 웹훅 주소를 출력이나 로그에 그대로 찍지 않습니다.
- 모든 출력은 한국어로 씁니다. 게임 이름, 개발사, 태그, 고유명사는 원어 그대로 둡니다.
- 사용자는 한국의 모바일 게임 UI 디자이너이며, Unity 로 혼자 인디게임을 만들려고 소재를 찾고 있습니다. 2D 와 3D 모두 가능하고, 연애 시뮬레이션 계열은 만들지 않습니다. 아이디어는 그 사람이 혼자 만들 수 있는 규모로 씁니다.

## 1. 오늘 리포트 받기

- 날짜는 한국 시간 기준 오늘입니다: `TZ=Asia/Seoul date +%F`
- 받을 파일 세 개 (모두 `https://raw.githubusercontent.com/subinlimied/indie-trending/main/` 아래):
  - `reports/steam/<날짜>.json` (Steam 공용 리포트)
  - `reports/itch/<날짜>.json` (itch.io 공용 리포트)
  - `reports/personal/<날짜>.json` (개인 범위 리포트. 없을 수도 있으니 404 면 건너뜁니다)
- Steam 과 itch 파일이 둘 다 404 이면 300초 기다렸다가 다시 시도합니다. 최대 12번까지 기다려도 없으면 "오늘 리포트가 아직 없어 건너뜁니다"라고 남기고 끝냅니다. 어제 날짜로 대체하지 않습니다.
- 상세 HTML: `https://subinlimied.github.io/indie-trending/reports/steam/<날짜>.html`, 같은 형식으로 `itch`.

## 2. 읽을 항목

Steam·itch 공용 리포트의 키:
- `pick`: 오늘의 선정 게임. `name`, `url`, `sub`(개발사 · 태그 · 출시일), `line`(순위·리뷰·동접·가격 변화), `badges`, `streak`(연속 선정 일수), itch 는 `thumb`. 있으면 `desc`(게임 설명 원문, 영어, 300자. Steam 은 스토어 짧은 설명, itch 는 목록 한 줄 소개 또는 페이지 og:description)
- `headline`: 큰 폭 변화 세 줄 (마크다운 링크 문자열)
- `sections[0].blocks[*].items`: 급상승 Top 3 항목들(블록 3개: 순위 상승폭 · 증가율 · 절대 규모). 항목마다 `name`, `url`, `line`, `sub`, `badges`, itch 는 `thumb`, 있으면 `desc`
- `sections[1].blocks[*].items`: 꾸준한 상승 Top 3 (같은 구조)
- `sections[2]`: 소재·장르 뜨는 것 (태그 표). `tables[0].cols` 는 [태그, 상승 묶음, 전체 비율, 배율, 예시, 연속], `rows` 의 각 행도 같은 순서의 문자열입니다(예: `["Casual", "12개 (40%)", "40%", "1.0×", "[게임](링크) · …", "3회차"]`). itch 는 표가 여러 개(`tables[*].title` 이 태그 · 장르 · 엔진)입니다.
- `sections[3]`: 할인·이벤트와 상승의 관계. `text`(한 줄 요약)와 `blocks`(오가닉 vs 할인 동반 목록)
- `notes`: 특이사항 문자열 목록

개인 리포트(`personal`)의 키:
- `platforms.steam` 과 `platforms.itch`: 각각 `top`(내 범위 Top 3. 항목마다 `name`, `url`, `line`, `sub`, `badges`, `tags`, `facts`, `thumb`, `same`), `pushed`(내 범위 밖으로 밀린 공용 게임: `name`, `url`, `reasons`, `role`), `why`(1위가 공용과 다른 이유 한 줄), `public`(공용 `pick`·`headline`·`top3`)
- `memo`: 오늘의 제작 메모 `{"name", "url", "platform", "text"}` (1위 게임의 차원·태그·가격·플레이 시간·데모·퍼블리싱)
- `weekly`: 월요일에만 값이 있고 평소엔 `null`. 있으면 `combos`(자주 오른 태그 조합)와 `fast`(리뷰가 빨리 쌓인 신작), `days`·`from`·`to`
키 이름이 조금 다르면 비슷한 항목을 찾아 쓰십시오.

오늘의 대상 게임 고르기: Steam `pick` → itch `pick` → 개인 리포트 `platforms.steam.top` · `platforms.itch.top` → Steam `sections[0]` 급상승 항목 순서로 모아 `url` 기준으로 중복을 빼고 **최대 6개** 로 자릅니다. 대형 퍼블리셔 작품이거나 `badges` 에 "본문 제외"가 있으면 뺍니다.

## 3. 게임마다 쓸 내용

게임 하나에 아래 항목을 씁니다. 글자 수를 지켜야 Discord 에서 읽힙니다.

| 항목 | 내용 | 길이 |
|---|---|---|
| 한 줄 요약 | 어떤 게임인지 한 문장. `desc` 가 있으면 그것을 근거로, 없으면 태그와 이름으로 추정하고 "추정"이라고 표시합니다. 제목 아래 첫 줄입니다. | 70자 이내 |
| 왜 뜨는가 | `line` 과 `headline` 의 숫자(순위 변화, 리뷰 증가, 할인 여부)를 근거로 한두 문장. 할인 동반이면 그렇다고 씁니다. | 120자 이내 |
| 핵심 루프 | 플레이어가 반복하는 행동 한 가지를 짧게. 태그로 추정하면 "추정" 표시. | 80자 이내 |
| 내가 만들 변주 | 이 게임의 핵심을 빌리되 혼자 만들 수 있게 줄인 아이디어 한 가지. 규모를 구체적으로(예: 2D, 스테이지 20개, 플레이 3시간). | 140자 이내 |
| 주의 | 경쟁 과포화, 대형 퍼블리셔, 멀티플레이 필수, 라이선스 문제처럼 따라 만들면 안 되는 이유가 있을 때만 씁니다. 없으면 항목을 넣지 않습니다. | 80자 이내 |

쓰기 규칙:
- 리포트에 없는 사실을 지어내지 않습니다. 게임 내용을 모르면 태그 기반 추정임을 밝힙니다.
- 조사와 어미를 생략하지 않은 완결된 문장으로 씁니다. 명사구로 끝내지 않습니다. 엠대시(—)를 쓰지 않습니다. 과장이나 광고 문구를 쓰지 않습니다.

## 4. 오늘의 제작 인사이트

Steam·itch 리포트 전체(선정 게임, 큰 폭 변화, 소재·장르 표, 할인 관계, 개인 메모)를 보고 **글머리표 3개** 로 씁니다. 각 항목은 두 문장 이내, 130자 이내입니다.

1. 흐름: 오늘 오른 게임들을 관통하는 공통점 하나 (메커닉, 소재, 가격대, 플랫폼 중)
2. 틈새: 소재·장르 표에서 배율이 높거나 공급이 적어 보이는 자리 하나. 근거가 약하면 "추정"
3. 오늘의 실험: 혼자서 하루 안에 해 볼 수 있는 작은 것 하나 (프로토타입 범위, 스토어 페이지 조사, 캡슐 스케치 등)

월요일이고 개인 리포트에 `weekly` 값이 있으면, 거기 있는 태그 조합·빠르게 크는 신작을 틈새 항목에 반영합니다.

## 5. Discord 메시지 구성

메시지는 **두 개** 로 나눠 보냅니다.

### 메시지 1: 게임 1~3번
```json
{
  "content": "🎮 **게임 트렌딩 활용 아이디어 · M월 D일 (요일)** · 오늘의 게임 N개",
  "embeds": [ ...게임 임베드 최대 3개... ],
  "allowed_mentions": {"parse": []}
}
```

### 메시지 2: 게임 4~6번 + 제작 인사이트
```json
{
  "content": "",
  "embeds": [ ...게임 임베드 나머지..., 인사이트 임베드 ],
  "allowed_mentions": {"parse": []}
}
```
게임이 3개 이하이면 메시지 1에 인사이트까지 넣고 메시지 2는 보내지 않습니다. 메시지 2는 메시지 1이 2xx 로 끝난 뒤 2초 쉬고 보냅니다.

### 게임 임베드 한 개의 형식
```json
{
  "title": "1 · 게임 이름",
  "url": "스토어 링크",
  "description": "한 줄 요약\n`Steam · 개발사 · 태그 · 가격`",
  "color": 색,
  "thumbnail": {"url": "썸네일 주소"},
  "fields": [
    {"name": "📈 왜 뜨는가", "value": "...", "inline": false},
    {"name": "🔁 핵심 루프", "value": "...", "inline": false},
    {"name": "🛠 내가 만들 변주", "value": "...", "inline": false},
    {"name": "⚠️ 주의", "value": "...", "inline": false}
  ]
}
```
- `description` 둘째 줄은 플랫폼 · `sub` 의 개발사와 태그 · 가격을 백틱으로 묶어 한 줄로 넣습니다.
- 썸네일: Steam 은 `url` 의 appid 로 `https://shared.fastly.steamstatic.com/store_item_assets/steam/apps/<appid>/capsule_231x87.jpg`, itch 는 항목의 `thumb`. 없으면 `thumbnail` 키를 넣지 않습니다.
- 주의 항목이 없으면 `fields` 에서 뺍니다.
- `color`: Steam `1726786`(0x1B2838), itch `16407644`(0xFA5C5C). 개인 범위에서 온 게임은 제목 끝에 " · 내 범위"를 붙입니다.

### 인사이트 임베드
```json
{
  "title": "💡 오늘의 제작 인사이트",
  "description": "• 흐름: ...\n• 틈새: ...\n• 오늘의 실험: ...",
  "color": 1338435,
  "fields": [{"name": "상세 리포트", "value": "[Steam](Steam HTML 주소) · [itch.io](itch HTML 주소)", "inline": false}]
}
```

### 제한
- 임베드 수: 메시지당 10개 이하
- `title` 256자, `description` 4096자, 각 field `value` 1024자, 한 메시지의 모든 임베드 글자 수 합 6000자 미만
- 넘치면 "왜 뜨는가"를 먼저 줄이고, 그래도 넘치면 게임 수를 줄입니다.

### 보내기
payload 를 파일로 쓴 뒤 다음 형태로 보냅니다.
```
curl -s -o /dev/null -w '%{http_code}' -H 'Content-Type: application/json' -d @payload1.json "$WEBHOOK"
```
응답 코드가 2xx 가 아니면 본문을 줄여 한 번만 다시 시도합니다.

## 6. 끝내기

보낸 메시지 수, 게임 수, 응답 코드만 짧게 남기고 끝냅니다.
