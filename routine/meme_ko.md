# 밈 한국어 설명 · 개인 채널 (예약 작업 지시문)

이 파일은 Claude Code 클라우드 예약 작업이 매일 읽어서 따르는 지시문입니다. 예약 작업의 프롬프트에는 웹훅 주소와 이 파일 주소만 있고, 실제 할 일은 여기에 적습니다. 가독성이나 구성을 바꾸고 싶으면 이 파일만 고치고 커밋하면 다음 실행부터 적용됩니다.

## 0. 원칙

- 이 작업은 클라우드에서 혼자 돌아갑니다. 저장소를 클론하거나 커밋하지 않고, 예약 작업 프롬프트에 적힌 Discord 웹훅 한 곳 외에는 아무 데도 전송하지 않습니다.
- 웹훅 주소는 프롬프트 첫 줄 `WEBHOOK=` 뒤의 값입니다. 그 값이 `https://discord.com/api/webhooks/` 로 시작하지 않으면 아무것도 보내지 말고 "웹훅 주소가 설정되지 않았습니다"라고만 남기고 끝냅니다. 웹훅 주소를 출력이나 로그에 그대로 찍지 않습니다.
- 모든 출력은 한국어로 씁니다. 밈 이름, 플랫폼 이름, 고유명사는 원어 그대로 둡니다.

## 1. 오늘 리포트 받기

- 날짜는 한국 시간 기준 오늘입니다: `TZ=Asia/Seoul date +%F`
- 주소: `https://raw.githubusercontent.com/subinlimied/indie-trending/main/reports/media/<날짜>.json`
- curl 로 받고, 404 이거나 JSON 이 아니면 300초 기다렸다가 다시 시도합니다. 최대 12번까지 기다려도 없으면 "오늘 리포트가 아직 없어 건너뜁니다"라고 남기고 끝냅니다. 어제 날짜로 대체하지 않습니다.
- 같은 날짜의 HTML 상세: `https://subinlimied.github.io/indie-trending/reports/media/<날짜>.html`

## 2. 읽을 항목

JSON 의 키:
- `shortform`: 틱톡·인스타 트렌드 목록. 항목마다 `title`, `url`, `summary`, `platforms`(목록, 예: `["TikTok"]`), `published`(UTC ISO), `status`(`submission`/`confirmed`/빈 값), `kinds`(출처 목록) 그리고 있을 때만 `about`(영어 설명 원문, 600자), `image`(엔트리 og:image 주소). ANTHROPIC_API_KEY 로 만든 날에는 `ko_what`·`ko_idea`(한국어 설명)도 있을 수 있는데, 이 작업은 그것과 별개로 직접 씁니다.
- `new_memes`: 새로 등록된 밈 목록 (같은 구조)
- `pick`: 오늘의 트렌드 한 건 (같은 구조 + `streak`, `reason`)
- `youtube`: `{"KR": {"status": "ok"|"skip"|"fail", "items": [...], "shorts": n, "total": n}, "US": {...}}`. 항목마다 `title`, `channel`, `views`(정수), `shorts`(true/false), `url`
- `reddit`: `[{"sub": "...", "status": "ok", "items": [{"title", "url"}]}]`
- `cross`(게임 교차): `[{"term", "game", "platform": "steam"|"itch", "game_url", "source"}]`
- `platform_counts`: `[["TikTok", 6], ...]` 쌍 목록. 그 밖에 `imgflip`, `trends`, `wiki`, `insight`(있을 때만)

`shortform` 을 먼저, 그다음 `new_memes` 를 이어 붙이고 `url` 기준으로 중복을 제거해 **최대 8개** 를 오늘의 밈으로 삼습니다. 설명의 근거는 `about` 이 있으면 `about`, 없으면 `summary` 입니다.

## 3. 밈마다 쓸 내용

밈 하나에 아래 네 항목을 씁니다. 항목마다 글자 수를 지켜야 Discord 에서 읽힙니다.

| 항목 | 내용 | 길이 |
|---|---|---|
| 한 줄 요약 | 이 밈이 무엇인지 한 문장. 제목 아래 첫 줄에 들어갑니다. | 60자 이내 |
| 유래와 쓰임 | 어디서 시작됐고 사람들이 어떤 식으로 쓰는지. 두 문장. | 160자 이내 |
| 활용 | 게임이나 숏폼 콘텐츠 소재로 쓸 구체적인 아이디어 한 가지. 메커닉, 연출, 캐릭터, 썸네일 중 하나를 고릅니다. | 100자 이내 |
| 주의 | 비하·혐오·저작권·보안 문제처럼 그대로 쓰면 안 되는 이유가 있을 때만 씁니다. 없으면 항목을 아예 넣지 않습니다. | 80자 이내 |

쓰기 규칙:
- 영어 원문에 없는 내용을 사실처럼 쓰지 않습니다. 추측이면 "추정"이라고 표시합니다.
- 조사와 어미를 생략하지 않은 완결된 문장으로 씁니다. 명사구로 끝내지 않습니다. 엠대시(—)를 쓰지 않습니다. 과장이나 광고 문구를 쓰지 않습니다.
- 사용자는 한국의 모바일 게임 UI 디자이너이며 혼자 만들 인디게임 소재를 찾고 있습니다. 활용 아이디어는 그 사람이 혼자 만들 수 있는 규모로 씁니다.

## 4. 오늘의 인사이트

리포트 전체(오늘의 밈, 유튜브 KR·US 인기 상위 5개 제목, Reddit 상위 글, 게임 교차)를 보고 씁니다. 문단이 아니라 **글머리표 3개** 로 씁니다. 각 항목은 두 문장 이내, 120자 이내입니다.

1. 오늘 밈들을 관통하는 흐름 하나 (대중문화나 숏폼 문법과 연결)
2. 과거에 비슷한 흐름으로 성공한 게임이나 콘텐츠 하나 (근거가 약하면 "추정")
3. 1인 개발자가 오늘 가져갈 수 있는 것 하나 (구체적으로)

## 5. Discord 메시지 구성

메시지는 **두 개** 로 나눠 보냅니다. 한 메시지에 밈을 다 넣으면 스크롤이 길어져 읽히지 않습니다.

### 메시지 1: 밈 1~4번
```json
{
  "content": "🧩 **밈 한국어 설명 · M월 D일 (요일)** · 오늘의 밈 N개",
  "embeds": [ ...밈 임베드 최대 4개... ],
  "allowed_mentions": {"parse": []}
}
```

### 메시지 2: 밈 5~8번 + 인사이트
```json
{
  "content": "",
  "embeds": [ ...밈 임베드 나머지..., 인사이트 임베드 ],
  "allowed_mentions": {"parse": []}
}
```
밈이 4개 이하이면 메시지 1에 인사이트까지 넣고 메시지 2는 보내지 않습니다. 메시지 2를 보낼 때는 메시지 1이 2xx 로 끝난 뒤 2초 쉬고 보냅니다.

### 밈 임베드 한 개의 형식
```json
{
  "title": "1 · 밈 이름",
  "url": "밈 링크",
  "description": "한 줄 요약",
  "color": 색,
  "thumbnail": {"url": "image 값이 있을 때만"},
  "fields": [
    {"name": "🧭 유래와 쓰임", "value": "...", "inline": false},
    {"name": "🎮 활용", "value": "...", "inline": false},
    {"name": "⚠️ 주의", "value": "...", "inline": false}
  ]
}
```
- `title` 은 번호와 밈 이름만 넣습니다. 밈 이름이 50자를 넘으면 앞 50자에 "…"를 붙입니다.
- `thumbnail` 은 항목에 `image` 값이 있을 때만 넣습니다. 없으면 키 자체를 넣지 않습니다. (리포트 JSON 도 이미지가 없으면 `image` 키를 넣지 않습니다.)
- 주의 항목이 없으면 `fields` 에서 뺍니다.
- `color` 는 `platforms` 의 첫 값에 따라: TikTok `16731212`(0xFF4C4C), Instagram `14177041`(0xD84F11), 그 외 `3358878`(0x33409E).

### 인사이트 임베드
```json
{
  "title": "💡 오늘의 인사이트",
  "description": "• 흐름: ...\n• 전례: ...\n• 가져갈 것: ...",
  "color": 1338435,
  "fields": [{"name": "상세 리포트", "value": "[미디어·밈 트렌드 전체 보기](HTML 주소)", "inline": false}]
}
```

### 제한
- 임베드 수: 메시지당 10개 이하
- `title` 256자, `description` 4096자, 각 field `value` 1024자, 한 메시지의 모든 임베드 글자 수 합 6000자 미만
- 넘치면 유래와 쓰임을 먼저 줄이고, 그래도 넘치면 밈 수를 줄입니다.

### 보내기
payload 를 파일로 쓴 뒤 다음 형태로 보냅니다.
```
curl -s -o /dev/null -w '%{http_code}' -H 'Content-Type: application/json' -d @payload1.json "$WEBHOOK"
```
응답 코드가 2xx 가 아니면 본문을 줄여 한 번만 다시 시도합니다.

## 6. 끝내기

보낸 메시지 수, 밈 수, 응답 코드만 짧게 남기고 끝냅니다.
